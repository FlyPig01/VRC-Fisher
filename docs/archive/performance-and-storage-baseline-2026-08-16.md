# 性能与存储预算

## 1. 口径

当前已有可构建的 C# 软件、Windows Graphics Capture、自动化测试、实际 Setup 和两个可由 CPU/DirectML 加载的候选 ONNX。Setup、无模型安装体积、模型文件体积以及离线单帧检测耗时已经实测；真实 VRChat 运行内存、CPU/GPU、端到端帧龄和自动钓鱼效果仍只是首版预算，不能作为实测结果发布。离线性能的完整环境、P50/P95 和测量边界见 [ONNX Runtime 单帧性能实测](onnx-runtime-benchmark-2026-08-15.md)。

## 2. 开发机存储

各环境独立估算，不能把它们与用户安装体积混为一谈：

| 项目 | 预计占用 | 主要来源 |
|---|---:|---|
| C# 应用开发 | 1-3 GB | .NET SDK、NuGet 缓存、Debug/Release/publish 产物 |
| 数据处理环境 | 实测约 156 MB | 仓库内 `.venv`，包含 Python 工具依赖和测试依赖 |
| CUDA 训练环境 | 实测逻辑大小约 3.28 GiB | 仓库内 `training/.venv`，包含 PyTorch 2.13 CUDA 13.0、Ultralytics 8.4、ONNX 和测试依赖 |
| uv 训练缓存 | 实测逻辑大小约 5.40 GiB | 仓库内 `training/.uv-cache`，用于离线复现和避免重复下载大型 CUDA wheel |
| 录屏、帧和数据集 | 数 GB 至数十 GB | 完全取决于时长、分辨率、抽帧间隔与实验数量 |
| 训练结果 | 每次数十 MB 至数百 MB | `.pt`、图表、日志和中间结果 |

同一张图片可能依次存在于抽帧、生成数据集和划分后数据集中，因此数据空间不能只按原视频大小估算。大文件均由 `.gitignore` 排除，但仍占开发机磁盘。

截至 2026-08-14，当前 `training/datasets` 逻辑大小约 182.7 MiB，`data_processing/output` 约 53.0 MiB。以上是当前样本规模的实测，不代表增加录屏后的上限。训练环境确认 `torch.cuda.is_available() == True`，在 RTX 4060 Laptop GPU 上使用 PyTorch 自带的 CUDA 13.0 运行库；系统未安装全局 CUDA Toolkit。

`.venv` 与 `.uv-cache` 可能使用硬链接共享同一物理磁盘块，所以不能把 3.28 GiB 与 5.40 GiB 简单相加作为实际占用。缓存可删除，代价是下次同步需要重新下载；环境可删除并由锁文件重建。两者都位于仓库内，不是最终用户安装体积。

## 3. 用户端存储

| 项目 | 当前实测或目标 |
|---|---:|
| 单个 DirectML Setup | 实测 57.47 MiB（60,265,022 字节） |
| DirectML 安装，不含模型 | 实测 215.75 MiB（226,229,549 字节，含卸载器） |
| 两个 YOLO11n ONNX | 实测合计 20.43 MiB（21,419,961 字节） |
| 安装目录含模型 | 目标低于 500 MB |
| Setup 硬上限 | 低于 1 GB |

Setup 只压缩一套 DirectML 发布源；其中仍可强制使用 CPU。上述 `0.1.1` 数据来自 2026-08-15 的最终构建和非 C 盘静默安装；每次发布都必须重新测量，不能沿用双构建时期的数据。

模型不放进 Setup。用户可以在软件中随时下载、更新或删除两个 ONNX，所有操作只影响安装目录下的 `models/`。

## 4. 运行资源

| 指标 | 首版目标 |
|---|---:|
| 空闲 WinUI 界面内存 | 100-180 MB |
| 完整识别运行内存 | 250-450 MB |
| 静止界面 CPU | 小于 1% |
| CPU 模式总 CPU | 小于 25% |
| DirectML 总 CPU | 小于 10% |
| DirectML 额外显存 | 小于 500 MB |
| UI 更新 | 5-10 Hz |
| VRChat 覆盖层 | 固定 `30 Hz`；运行模式仅更新热键提示，调试模式显示最新原始推理结果 |
| locator 等待阶段 | `960 x 960`；自动间隔 `80-250 ms` |
| Hooking 双模型阶段 | `960 + 640`；自动间隔 `80-250 ms` |
| locator 小游戏复查 | `960 x 960`；自动间隔 `250-1000 ms`，只校验缓存位置 |
| minigame 小游戏阶段 | `640 x 640`；自动选择 `40/50/67 ms`，约 25/20/15 Hz |
| 识别管线 | 不积压旧帧；关键目标持续丢失时立即重新定位 |

这些百分比依赖具体 CPU、分辨率、模型输入尺寸和 VRChat 负载。2026-08-15 离线实测中的独立 CPU-only 数据只作为历史性能对照；当前产品的 CPU 模式来自 DirectML 包。运行页启动时检测一次静态硬件和实际后端，但不持续轮询利用率；详细性能仍以开发基准和现场记录为准。

DirectML 也可能在小模型上因 GPU 调度与数据拷贝开销而不如 CPU；`Auto` 必须可靠回退，用户也可直接切换为同一安装包内的 CPU。项目不再为这一差异维护独立 CPU-only 发行包。

## 5. 时间与实时性

实时性以“画面产生到决策完成的帧龄”衡量，而不是只看单次 ONNX 推理时间。需要记录：

- 屏幕捕获间隔；
- locator 与 minigame 各自推理 p50/p95；
- 预处理、后处理和裁剪耗时；
- 决策时帧龄 p50/p95；
- 丢帧数量和连续落后时长；
- VRChat 本身的帧时间变化。

WGC捕获会话持续接收通知，但只在读回前通过帧需求门禁领取一张最新帧；未到识别时间的帧直接释放，不创建CPU像素缓冲区。处理能力低于捕获速率时丢弃旧帧，而不是排队等待；自动控制宁可降低检测频率，也不能使用几百毫秒前的状态。

locator 从 `640` 提高到 `960` 后，单次输入像素数为原来的 2.25 倍。小游戏 UI 在一轮内通常不移动，因此高频 minigame 使用固定原始裁剪框；若局部目标持续丢失，再恢复 locator 高频重新定位。

2026-08-15 历史 CPU-only 检测器的 locator、locator + minigame、缓存 minigame P95 分别为 `65.21/119.79/24.79 ms`；DirectML 三种路径的 P95 均低于 `17 ms`。当前 DirectML 包强制 CPU 的实测见基准文档；CPU 双模型复查余量不足，因此正式运行使用受限自动调频。

自动调频只记录已经发生的 ONNX 检测，不额外捕获或执行模型；WGC读回由同一阶段间隔门禁控制：

| 项目 | 实现 |
|---|---|
| 负载隔离 | `locator`、`locator + minigame`、`cached minigame` 分开统计；捕获读回另行记录 |
| 预热与窗口 | 每类丢弃前 10 次；至少 30 个有效样本；固定保留最近 120 个 `double` |
| 检查周期 | 每 5 秒计算一次 P95；每类窗口约 960 字节，三类合计约 2.9 KiB |
| 调节规则 | locator `P95 / 0.65`；Hooking `双模型 P95 / 0.80`；小游戏按 `P95 / 0.70` 选择 40/50/67 ms 档位；面板复查 `双模型 P95 x 4` |
| 迟滞 | 目标变慢立即增加间隔；连续稳定 30 秒后才按小步降低间隔 |
| 安全上限 | `80-250 / 80-250 / 40、50、67 / 250-1000 ms`；不允许无限降频 |

自动调频热路径只增加两次 `Stopwatch` 时间戳读取、一次固定数组写入和几个数值比较；P95 排序最多处理 120 个值且每 5 秒才发生一次，使用栈内存。运行和调试模式都在 `60-75 ms` 脉冲期间继续缓存区域推理，使视觉结果可以提前请求释放；运行模式不创建可视化检测数组，调试模式才把最终结果交给 `30 Hz` 最新帧缓冲。覆盖层绘制本身不调用 ONNX。真实 VRChat 验收必须分别记录两种模式的 CPU、帧龄和 VRChat 帧时间。

CPU 后端首次使用保守初值 `100/150/50/500 ms`，DirectML 首次使用 `80/80/40/250 ms`。调节画像按实际后端、硬件、模型版本和捕获分辨率匹配，保存到 `<安装目录>/config/performance-profiles.json`；任一项变化就重新采样。

若缓存小游戏所需间隔超过 `67 ms`，软件保持 `67 ms` 并显示性能不足警告；自动输入不能据此宣称稳定。该边界保证性能适配不会退化成无限降频。

## 6. 测试矩阵

`models/v0.1.0` 已完成 CPU/DirectML 加载和单帧结果检查；正式现场验收仍需在相同录屏和现场场景下分别测试：

| 安装包 | 软件设备选项 | 应验证的实际后端 |
|---|---|---|
| DirectML | Auto | DirectML 或有记录的 CPU 回退 |
| DirectML | CPU | CPU |
| DirectML | GPU | DirectML；失败必须报告 |

每组至少记录软件版本、模型版本、显示器分辨率、CPU/GPU、VRChat 状态、内存峰值、CPU、GPU、显存、推理 p95、帧龄 p95 和丢帧率。

## 7. 发布门槛

以下任一情况发生时不得发布：

- 安装目录或 Setup 达到 1 GB；
- 内存持续增长；
- 空闲界面持续占用明显 CPU；
- 推理队列积压旧帧；
- DirectML 初始化失败却仍显示 GPU 正常；
- 开启或关闭 GUI 明显改变识别正确性；
- 空闲 UI 刷新显著影响 VRChat 帧率；
- 自动运行出现“设备性能不足”且尚未通过现场控制验收；
- 资源数字来自估算而非正式构建实测。
