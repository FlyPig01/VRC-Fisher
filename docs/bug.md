# 缺陷记录

更新日期：2026-08-16

## 本次修复问题

### BUG-019：实际运行设备状态不符合后台工作流

**状态**：已修复，纳入 `app-v0.1.3`（2026-08-16，尘易飞）。

**现象**：软件停止时“实际使用”始终显示“不可用”；成功启动后软件位于后台，用户无法及时查看；停止后结果又被清空。

**原因**：界面直接显示当前推理会话。会话仅在自动钓鱼运行期间存在，停止时会被释放并重置，因此该字段无法回答用户真正关心的“上一轮实际使用了什么设备”。

**解决方案**：

- 当前会话状态与最近一次成功运行结果分开保存；
- 将“实际使用”改为“最近一次运行”，成功建立推理会话后记录 CPU/GPU、设备名称和回退原因，停止后继续显示；
- 当前软件进程尚无成功记录时显示“暂无运行记录”；用户修改运行设备后显示“等待下次运行确认”，避免把旧结果误认为当前配置；
- 不在软件启动时预加载模型或创建测试会话，避免无意义占用内存和显存。

**验收**：启动成功后切回软件或停止运行，仍能看到本轮实际设备；切换运行设备后不会显示误导性的旧结果；首次启动不再显示“不可用”。

**实现结果**：运行快照已拆分当前会话与最近一次成功运行；停止不再清除历史结果，设备选择变化由结构化状态显示“等待下次运行确认”，且未增加后台推理会话。

### BUG-020：按 F8 启动时进程崩溃

**状态**：已修复，纳入 `app-v0.1.3`（2026-08-16，尘易飞）。

**现象**：VRChat 位于前台时按 `F8`，VRC-Fisher 直接退出；右上角没有启动、停止或失败提示，也没有抛竿。

**已确认原因**：Windows 应用事件在 2026-08-16 01:03:39 记录 `.NET Runtime 1026`。`WgcCaptureAdapter.CopyBgra` 将 WinRT `IInspectable` 直接强制转换为自定义 `IMemoryBufferByteAccess`，触发未捕获的 `InvalidCastException`。异常从 `async void` 的 WGC 首帧回调逃逸，CoreCLR 终止进程，异常码为 `0xe0434352`。首帧尚未交给启动事务，所以覆盖层和抛竿都没有发生；应用日志也来不及可靠写入。

**解决方案**：

1. **修正 WinRT/COM 访问**：使用 C#/WinRT 的 `As<IMemoryBufferByteAccess>()` 或显式 `QueryInterface` 获取 `IMemoryBufferByteAccess`，禁止直接强转；复制前校验指针、容量、起始偏移、步幅和最终读取边界。
2. **隔离帧回调异常**：首帧处理改为受控异步任务，完整捕获回调中的异常，任何异常都不得越过 WGC 事件边界成为进程级未处理异常。
3. **接入启动事务**：为捕获层增加结构化失败通知。首帧前失败时使等待首帧的任务以异常结束，由 `RuntimeController` 统一停止捕获、释放模型会话和鼠标输入，并恢复“已停止”状态；释放 `_frameGate` 后再执行停止，避免回调自等待死锁。
4. **补充前台反馈**：按热键后立即在 VRChat 右上角显示“正在启动”；首帧与推理成功后切换为停止热键提示；启动失败时显示醒目的失败提示并保持数秒，同时在软件内保留完整错误，不抢占 VRChat 焦点。
5. **补充最后防线**：记录应用级未处理异常并立即释放鼠标，但全局处理器只用于诊断，不能代替捕获层的正常错误传播。
6. **增加测试与现场门禁**：自动测试覆盖首帧前捕获失败、运行中失败回滚、输入释放、回调异常隔离和运行设备历史；真实 WGC 首帧、覆盖层提示与连续启动/停止由 Windows 现场回归验证。

**验收**：

- 在当前 Windows 11、VRChat 和显卡环境中连续启动/停止至少 10 次，进程不退出；
- 按 `F8` 后立即出现右上角启动反馈，成功后只抛竿一次并显示停止热键；
- 人为制造捕获失败时，软件保持运行、鼠标输入已释放，右上角和软件内均显示明确错误；
- CPU、GPU 和自动选择三种模式均完成一次真实首帧测试；
- Windows 应用事件中不再出现来自 `WgcCaptureAdapter.CopyBgra` 的未处理异常。

**发布处理**：`app-v0.1.2` 保留为该缺陷的历史复现 tag，不再作为可用版本发布；修复版本使用新 tag `app-v0.1.3`，不改写历史 tag。

**自动验证**：Release 配置 75 项测试全部通过；新增测试覆盖首帧前失败、运行中失败回滚、输入释放、异常隔离、运行设备历史和 20 种语言资源一致性。正式 `app-v0.1.3` Setup 已通过发布脚本校验；真实 WGC 连续启停仍保留为发布后的现场回归项目。
