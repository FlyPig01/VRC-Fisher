### BUG-013：模型下载速度过慢

**状态**：已修复（2026-08-16，尘易飞）。

**现象**：两个 ONNX 下载耗时明显过长，进度增长缓慢，网络波动后恢复能力较差。

**原因判断**：需要检查 GitHub Release 连接建立、文件串行下载、连接复用、超时重试和临时文件处理；不能直接把问题归因于模型大小。

**解决方案**：

- 复用应用级 `HttpClient`，直接流式写入安装目录下的下载暂存文件；
- 两个模型和侧车文件采用有限并发，避免无上限并发占满网络和磁盘；
- 支持 HTTP Range 续传、指数退避重试和断点文件校验；
- 下载完成后继续校验清单中的大小与 SHA-256，再原子替换正式模型；
- 下载任务开始时固定版本、下载地址、文件大小和 SHA-256；断网恢复前重新读取清单，清单指纹未变化才允许 Range 续传；
- 如果期间发布了新模型，旧版本的 `.part` 文件不得拼接到新模型，必须丢弃旧暂存并重新下载新版本；
- 正式替换前再次检查最新清单；已安装的旧模型继续保留，只有新文件完整校验后才原子替换；
- 错误信息区分连接失败、限速、超时、磁盘不足和校验失败。

**验收**：同一网络下速度明显稳定；断网恢复后，在模型版本未变化且断点文件有效时可以续传，不限制断网持续时间；断网期间发布新版本时不会混用新旧文件，会重新下载新版本；失败不会损坏已安装模型。

### BUG-014：切换页面会终止模型下载

**状态**：已修复（2026-08-16，尘易飞）。

**现象**：在模型页点击下载后切换到运行、指南或设置页，下载立即终止。

**原因判断**：下载任务或取消令牌绑定了 `ModelsPage` 生命周期，页面卸载时错误地取消了业务任务。

**解决方案**：

- 新增应用级模型下载协调器，由 `App` 持有唯一下载任务和状态；
- 页面只订阅进度和状态，离开页面时仅取消订阅，不取消下载；
- 返回模型页后恢复显示当前文件、进度、速度和错误状态；
- 只有用户确认取消、软件退出或不可恢复错误才停止任务；
- 下载暂存、校验和最终替换继续由模型基础设施层负责。

**验收**：下载期间反复切换页面不会中断；返回模型页后显示连续进度；不会创建重复下载任务。

### BUG-015：硬件信息混乱且系统版本识别错误

**状态**：已修复（2026-08-16，尘易飞）。

**现象**：CPU、GPU、系统和推理状态混在一个区域；GPU 重复显示，Windows 11 build `26200` 被显示为 Windows 10。

**原因判断**：Windows 注册表的 `ProductName` 在部分 Windows 11 系统中仍保留 Windows 10 文本；显卡列表同时包含重复注册项、软件适配器和同一设备的多个记录。

**解决方案**：

- 界面拆分为 CPU、GPU、系统和推理四个清晰区域；CPU/GPU 信息改用固定列宽的表格，型号左对齐，编号和数值右对齐，数据行不再重复拼接类别文字；
- 使用系统 build 号判断主版本，build 大于等于 `22000` 显示 Windows 11，再组合版本和 build；
- 以 DXGI 适配器的 LUID 或设备标识去重，稳定保留 NVIDIA、AMD、Intel 硬件设备；
- 识别并排除 Microsoft Basic Render Driver 等软件适配器，不混入物理 GPU；
- 用户选择和实际推理设备只放在推理状态区，未启动时明确显示“尚未建立推理会话”。

**验收**：当前电脑正确显示 Windows 11 25H2 build `26200`；RTX 4060 和 Radeon 780M 各出现一次；信息可快速区分。

### BUG-016：使用指南图片说明不准确

**状态**：已修复（2026-08-16，尘易飞）。

**现象**：当前文案让用户误以为点击图片会直接进入 VRChat 世界，实际只会打开该世界的官方网页信息。

**解决方案**：将说明改为“点击图片查看此世界的网页信息”，保留整张图片作为唯一链接，不显示冗余网址或按钮；进入世界仍由用户在 VRChat 中完成。

**验收**：页面不再暗示自动进入世界，点击图片只打开预定义的 VRChat 官方世界页面。

### BUG-017：运行/调试图标位置错误

**状态**：已修复（2026-08-16，尘易飞）。

**现象**：三角形和虫子图标被放在设置页的模式选项中，而需求是让它们表示透明屏幕覆盖层当前的工作模式。

**解决方案**：

- 设置页模式选项改回纯文字，保持简洁；
- 透明覆盖层右上角显示当前模式：运行模式为三角形，调试模式为虫子；
- 图标与退出热键提示一起显示，覆盖层以 `15 Hz` 刷新；
- 状态变化经过防抖，复用现有识别结果，不额外增加截图或 ONNX 推理。

**验收**：设置页不再显示两枚图标；启动后透明覆盖层显示正确模式图标，切换模式后稳定更新且不闪烁。

### BUG-018：两个模型已就绪但顶部仍显示模型缺失警告

**状态**：已修复（2026-08-16，尘易飞）。

**现象**：模型页中 `locator.onnx` 和 `minigame.onnx` 均显示“已就绪”，但窗口顶部仍显示“必需模型缺失或损坏，请打开模型页，下载或更新完整模型包，然后重试”。切换页面或重新打开模型页后，警告仍可能保留。

**原因判断**：模型页读取的是 `ModelCatalog` 的最新校验结果，顶部警告读取的是运行控制器之前发布的 `ModelsRequired`/`ModelsUnavailable` 状态。模型下载或刷新完成后只更新了就绪标志，没有同步清理已经失效的运行警告，导致同一份状态在界面上出现冲突。

**解决方案**：

- 将必需模型的“存在、大小、SHA-256、许可证文件和 `automatic_allowed`”校验结果作为统一就绪状态，由模型目录刷新、下载完成和删除完成统一发布；
- 当两个模型均通过校验且检测运行时可用时，清除仍然属于模型缺失的旧运行状态，并关闭顶部警告；
- 如果任一模型缺失、损坏、版本清单无效或自动输入未获许可，继续显示对应警告，不因单个文件显示“已安装”而提前清除；
- 模型页和运行页都从同一份最新状态渲染，切换页面只改变订阅，不保留过期警告；
- 增加状态转换测试：缺失→下载完成、损坏→修复、删除→缺失，以及刷新页面后警告状态的一致性。

**验收**：两个模型和配套文件均显示“已就绪”后，顶部不再显示模型缺失警告；任一模型被删除或篡改后，警告重新出现；页面切换、软件重启和模型更新不会产生旧警告残留。
