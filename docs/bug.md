## FIX-01：安装包与运行环境

**状态：已修复**

### 问题

安装器同时显示安装类型和运行组件，DirectML 与 CPU-only 的关系不清楚；目录页还把约 `229.7 MiB` 的基础安装错误显示为 `5.1 MB`。

### 统一方案

- 删除独立 CPU-only 构建，只发布 DirectML 版本；
- 删除安装类型、组件选择和整页运行环境选择；
- DirectML 包继续提供 `自动 / GPU（DirectML）/ CPU`，三种模式使用同一份 ONNX；
- 程序文件改为无条件安装，让目录页正确统计完整基础安装空间；
- 模型不放入 Setup，另行说明约 `20.5 MiB` 的下载和磁盘占用；
- 切换 CPU、GPU 或自动模式不重新训练、转换或下载模型。

### 验收

- Setup 不再出现安装类型或运行组件页面；
- 目录页与无模型安装目录的实测误差不超过 `5 MiB`；
- 安装后可直接选择自动、GPU 或 CPU；
- 仓库和构建目录不再产生 CPU-only publish。

## FIX-02：Release、安装目录与卸载

**状态：已修复**

### 问题

应用 Release 生成了无人读取的 Setup `.sha256` 附件；安装目录规则和卸载清理范围也需要统一。

### 统一方案

- `app-v*` 只包含 `VRC-Fisher-Setup-x64.exe`，不再生成独立 `.sha256`；
- `models-v*` 保留 `model-manifest.json`，软件继续用其中的大小和 SHA-256 校验模型；
- 程序、模型、设置、下载和日志全部保存在用户选择的安装目录；
- 允许 Windows 必需的卸载注册信息、开始菜单/桌面快捷方式和安装临时文件位于系统目录；
- 完整卸载删除程序、模型、设置、下载、日志、快捷方式和卸载注册信息；
- 不删除 Prefetch、系统事件、Defender 记录和驱动缓存；
- 卸载清理只允许针对已验证的 VRC-Fisher 安装目录及明确子目录。

### 验收

- 应用发行目录只有一个 Setup；
- 模型校验能力不受影响；
- 软件安装到任意本地磁盘都能正确注册和卸载；
- 卸载后不残留 VRC-Fisher 主动管理的数据。

## FIX-03：模型下载进度

**状态：已修复**

### 问题

下载进度直接显示七八位原始字节数，不便阅读。

### 方案

- 根据总大小选择 `B / KB / MB / GB`；
- 已下载量和总大小始终使用同一单位并保留一位小数；
- 下载过程中不切换单位；
- 示例：`locator.onnx：4.1 / 20.5 MB`；
- 20 种语言共用国际单位，不再分别翻译“字节”。

### 验收

- `0`、不足 `1 KB`、超过 `1 GB` 和未知总大小均可正确显示；
- 进度条仍使用原始字节计算比例；
- 界面不再显示冗长的原始字节数。

## FIX-04：热键与 VRChat 前台限制

**状态：已修复**

### 问题

当前热键只能从下拉框选择并长期占用系统全局组合；切出 VRChat 后只暂停输入，没有完整停止运行。

### 统一方案

- 设置页显示当前热键和“修改”按钮，不再使用固定下拉框；
- 修改流程为：第一次确认 → 按键捕获 → 第二次确认；`Esc` 取消；
- 功能键可单独使用，字母和数字必须搭配 `Ctrl / Alt / Shift`；拒绝系统保留组合；
- 保存前及软件启动时临时调用 `RegisterHotKey` 检查当时的全局冲突，成功后立即注销；
- 正常运行使用按键状态监听和按下沿防抖，不长期注册全局热键；
- 只有 `VRChat.exe` 位于前台时热键才生效；
- 切出、最小化、锁屏、休眠或 VRChat 退出时立即释放鼠标并完整停止；返回游戏后不自动恢复；
- 不注入、不修改、不挂钩 VRChat 进程。

### 提示边界

- 检测成功只显示“未发现全局注册冲突”；
- 软件无法检测 VRChat 内部绑定和其他普通键盘监听；
- 修改失败时保留原热键，并给出明确原因。

### 验收

- 可以直接按键设置合法组合，并经过两次确认；
- VRChat 不在前台时按热键没有反应；
- 切出后运行状态变为已停止，鼠标立即释放；
- 长按热键只触发一次；
- 20 种语言不再把它错误称为长期全局热键。

## FIX-05：启动链路、运行状态与硬件信息

**状态：已修复**

### 问题

- 屏幕捕获把 `IDXGISurface` 的 IID 当成 `IDXGIDevice`，导致捕获启动失败且无法抛竿；
- 软件在捕获真正成功前就显示“已启动”；
- 热键后台线程直接更新 WinUI，错误提示可能再次触发跨线程异常；
- 模型目录和运行快照是两个状态源，可能同时显示“未安装”和“已就绪”；
- 运行页没有静态硬件与实际推理设备信息。

### 统一方案

- 使用正确的 `IDXGIDevice` 接口，并集中管理原生 IID 与 HRESULT 检查；
- 启动改为事务流程：`已停止 → 正在启动 → 运行中`；模型、推理、捕获和首帧全部成功后才显示运行中并抛竿；
- 任一步失败都回滚资源、释放鼠标并显示失败阶段；
- 后台线程只发布状态，所有 WinUI 更新经 `DispatcherQueue` 执行；
- 模型刷新、下载、删除和校验统一更新同一份运行快照；
- 软件启动时只检测一次静态硬件：CPU 型号与核心/线程、GPU 名称/显存/驱动、内存、Windows 版本和 x64；
- 界面显示“运行设备”和“实际使用”，不显示 `Provider` 内部术语；自动回退 CPU 时说明原因；
- 不持续轮询硬件利用率，不增加诊断页面，不读取序列号。

### Windows 范围内的通用性要求

- **平台实现隔离**：Core/Application 只依赖捕获、推理、输入、硬件信息和 UI 通知接口；WGC、COM、DirectML、Win32 与 WinUI 代码分别限制在 Infrastructure/Desktop；
- **结构化设备状态**：运行快照使用“用户选择、实际后端、实际设备、是否回退及原因”等结构化字段，内部 Provider 字符串只写日志；
- **并发启动保护**：启动、停止、切出和设备切换共用串行门禁与取消令牌；重复启动、启动中停止和快速切换必须幂等且完整回滚；
- **分层测试**：事务启动和状态同步使用模拟捕获/推理做平台无关测试；WGC、COM、DirectML 和 WinUI 调度使用单独的 Windows 集成测试；
- **硬件检测非阻塞**：硬件信息读取失败只显示“无法获取”，不得阻止捕获、推理和自动钓鱼；
- 通用范围限定为 Windows 10/11 x64、ONNX Runtime CPU/DirectML，以及支持 WGC/DirectX 的 NVIDIA、AMD、Intel 设备，不承诺 Linux、macOS 或损坏驱动环境。

### 目标流程

```text
检查 VRChat、模型和前台状态
→ 初始化推理与捕获
→ 验证首帧
→ 显示运行中
→ 左键抛竿
→ 识别感叹号和小游戏
```

### 验收

- 捕获或推理失败时不发送鼠标输入，也不显示运行成功；
- 首个有效帧只抛竿一次；
- 所有模型状态显示一致且实时更新；
- 后台错误不会再产生 UI 跨线程异常；
- 多 GPU 环境能区分设备，CPU 回退显示准确；
- 启动链路测试覆盖成功、捕获失败和推理失败。

## FIX-06：使用指南与适用世界

**状态：已修复**

### 问题

软件没有说明只支持特定世界，也没有直观的开始步骤。

当前仅支持：

<https://vrchat.com/home/world/wrld_ae001ea3-ed05-42f0-adf2-3d47efd10a77/info>

### 方案

- 新增“使用指南”页面，导航顺序为：`运行 → 模型 → 使用指南 → 设置`；
- 使用本地封面作为页面主体：

```text
assets/worlds/wrld_ae001ea3-ed05-42f0-adf2-3d47efd10a77/cover.jpg
```

- 封面为 `1795×894`、约 `0.282 MiB`，按约 `2:1` 显示，不裁掉主体；
- 整张封面可点击并打开官方世界页面；界面不显示原始 URL，也不增加重复按钮；
- 图片随安装包发布，页面不联网下载图片；
- 封面下只显示三个步骤：进入世界、准备软件、按热键；
- 简短提示其他世界不受支持，世界 UI 更新后可能需要更新模型；
- 页面和使用手册保持一致，并提供 20 种语言；
- 图片授权与代码 MIT 许可证分开记录。

### 验收

- 用户无需查看仓库即可知道支持哪个世界和如何启动；
- 断网时封面仍能正常显示；
- 点击封面只打开预定义的 VRChat 官方地址；
- 页面没有冗余网址或按钮，并与现有 WinUI 视觉一致；
- 增加更多世界时不需要重写页面结构。

## 已确认的技术边界

- 同一份 FP32 ONNX 同时用于 CPU 和 DirectML，切换设备不需要重新训练；
- 模型下载器按兼容的 `models-v*` 版本选择模型，不依赖 GitHub 的 Latest 标签；
- 本轮不增加 CUDA、增量更新器或远程封面图片。
