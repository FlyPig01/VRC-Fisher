## BUG-036：其他物体被误识别为感叹号

**状态**：未解决，待补充负样本并重新训练 locator。

**现象**：运行时仍可能把非感叹号物体识别为 `bite_indicator`，导致错误进入等待鱼上钩或后续钓鱼流程。此前将感叹号运行阈值提高到 `0.60` 只能降低部分低置信度误报，不能替代模型训练。

**证据与处理方向**：新增反馈视频 `反馈8` 已完成审核，共 `91` 张图片，`91` 张均为空标签负样本，当前仍在 `data_processing/work/annotations/反馈8/`，尚未进入训练集。由于 `bite_indicator` 与 `minigame_panel` 互斥，这 `91` 张只有在确认画面中也没有小游戏面板时，才能作为 locator 空标签负样本；如果其中出现面板，必须改标 `minigame_panel`，不能保留空标签。现有 locator 训练集为 `2308` 张图片，其中 `1118` 张负样本、`272` 个 `bite_indicator` 框；加入本批次后预计为 `2399` 张图片、`1209` 张负样本。数量足够进行一轮针对性训练，但样本来自单段视频，场景多样性仍不足，不能据此承诺误报问题已解决。

后续按以下顺序处理：

1. 将 `反馈8` 的空标签提交到 locator 数据集，保持原始视频名和帧名对应。
2. 继续补充不同鱼获画面、UI 装饰物、视角、亮度和距离下的误报负样本；负样本重点覆盖模型曾经给出较高置信度的非感叹号物体。
3. 使用图片级分层随机划分进行训练和验证，不把同一批次全部放入训练集；同时保留一组只用于人工视频审核的反馈视频。
4. 验收重点是 `bite_indicator` 的误报率和误触发次数，不能只看总体 mAP；感叹号宁可少触发，也不能把普通物体当成感叹号。

未完成新模型验收前，不替换当前正式模型。

## BUG-037：快速移动目标下小游戏控制容易失败

**状态**：上一版修复实机表现更不稳定；已根据调试日志完成第二版修复，待实机验证。

**现象**：问题不只是目标移动速度高，而是目标和滑块可能同时向相反方向运动：

- `moving_target` 位于 `catch_zone` 下方并向上移动，而 `catch_zone` 正在向下移动，下一次识别时滑块已经偏下；
- `moving_target` 位于 `catch_zone` 上方并向下移动，而 `catch_zone` 正在向上移动，下一次识别时滑块已经偏上。

第一版虽然补上了目标运动预测，却把最近三帧的目标趋势完整外推到下一次反馈。调试日志显示随机目标可能在一个反馈周期内反向；反馈周期达到 `87–150 ms` 时，旧方向会被外推过远，反而让滑块纠正过激。

**实现内容**：

第二版保留“双时刻预测”和滑块动力学，只修正随机目标的速度估算与短期外推：

1. **分开估算速度**：滑块继续使用最近三张有效画面，降低识别框抖动的影响；目标改用最近两张有效画面，使随机反向在下一次识别时立即生效。速度仍是带符号的单个数。
2. **保留帧龄补偿**：从截图时刻补偿到当前决策时刻时，目标使用刚测得的完整速度。这段时间较短，不能因为后续趋势不确定而削弱当前坐标补偿。
3. **衰减未来外推**：从当前时刻预测到下一反馈时刻时，目标速度按“最近目标识别间隔 / 预计反馈周期”衰减，并限制在 `0.50–0.75`。反馈越慢，随机目标继续保持当前方向的可信度越低；滑块仍按完整速度和实测加速度预测。
4. **同时检查两个时刻的距离**：分别检查“当前预测位置”和“下一反馈预测位置”时，目标是否仍在滑块允许范围内，以及距离上、下边界还剩多少。当前已经越界时立即纠正；当前尚未越界但下一反馈时刻会越界时，本帧提前改变输入；两个时刻都安全时才允许保持原计划。
5. **处理相反运动**：
   - 目标在滑块下方且目标速度为正、滑块速度为负时，使用下一反馈预测距离判断下边界是否会被穿过；会穿过就立即取消释放计划并启动向上控制，不能继续沿用滑块下落的旧计划。
   - 目标在滑块上方且目标速度为负、滑块速度为正时，使用下一反馈预测距离判断上边界是否会被穿过；会穿过就立即取消按住计划并释放，不能继续沿用滑块上升的旧计划。
   - 目标已经在滑块内部时，仍然执行同样的当前时刻和下一反馈时刻预测；不能因为“当前已包含”就跳过下一时刻的越界检查。
6. **替换计划而不是叠加计划**：新识别结果到达后，重新计算当前预测、下一反馈预测和边界距离，并取消尚未执行的旧计划。新计划只从当前真实按键状态开始，不能把旧计划剩余按压时间加到新计划上。
7. **边界和失效处理**：滑块到达运动边界时，禁止继续发送无法产生有效位移的方向；识别结果过期或缺少任一组件时释放并等待下一张有效坐标。边界保护只处理确实存在的物理边界，不使用没有数据依据的位移上限替代预测。

诊断日志新增目标外推权重和实际用于规划的目标速度。按压超时也改为比较“实际释放时刻”和最后一次计划的绝对释放时刻，不再把整段累计按住时间与最后一次剩余计划时长比较，避免产生假警告。

单元测试覆盖目标突然反向、`60/90/120/150 ms` 反馈周期、帧龄补偿以及重新规划后的绝对释放时刻。实机验收重点是快速随机目标反向后不再触发过度纠正，同时不能破坏普通难度下已经稳定的控制。
