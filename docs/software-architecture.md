# 软件架构

## 1. 边界

正式软件在 Windows 上捕获用户选择的完整显示器，识别以下流程并控制鼠标：

```text
抛竿 -> 等待感叹号 -> 收钩 -> 控制小游戏 -> 收杆/拾取 -> 下一轮
```

软件不注入 VRChat、不读取游戏内存、不修改网络或游戏文件。视觉模型是运行时判断的唯一来源；OpenCV 模板匹配、固定坐标和颜色阈值都不是识别回退方案。模型或关键目标缺失时必须停止输入。

## 2. C# 解决方案

目标目录：

```text
app/
  VrcFisher.sln
  src/
    VrcFisher.Core/
    VrcFisher.Application/
    VrcFisher.Infrastructure/
    VrcFisher.Desktop/
  tests/
    VrcFisher.Core.Tests/
    VrcFisher.Application.Tests/
    VrcFisher.Infrastructure.Tests/
```

| 项目 | 职责 |
|---|---|
| `Core` | 状态机、检测结果、控制决策、时间与输入接口；不依赖 WinUI、ONNX 或 Win32 |
| `Application` | 运行用例、生命周期、配置验证、状态快照和安全停机 |
| `Infrastructure` | 屏幕捕获、ONNX、模型下载、文件存储、窗口检测与鼠标输入 |
| `Desktop` | WinUI 3 页面、ViewModel、导航、本地化和依赖注入入口 |

依赖方向固定为：

```text
Desktop ---------> Application ---------> Core
                         ^
                         |
Infrastructure ----------+
```

ViewModel 不直接调用 ONNX Runtime、GitHub API 或 Win32。后台服务只向 UI 发布不可变、低频的运行快照。

## 3. 实时管线

```text
Windows Graphics Capture（完整显示器）
  -> 只保留最新帧的有界缓冲
  -> locator.onnx
     -> 没有 fishing_ui_group：更新全局状态
     -> 找到 fishing_ui_group：按框加边距裁剪原始帧
        -> minigame.onnx
        -> 时序确认与状态机
        -> Win32 鼠标输入
  -> RuntimeSnapshot
  -> WinUI 3（5-10 Hz）
```

`locator.onnx` 在完整屏幕上解决 UI 移动和缩放；`minigame.onnx` 在局部原始细节上识别轨道、控制条、目标和进度条。中间物件无论是鱼、齿轮或其他外观，都归一为 `target` 类。

实时约束：

- 捕获与识别目标为 30 FPS；
- locator 默认每 3 帧运行一次，小游戏存在时 minigame 逐帧运行；
- 缓冲只保留最新帧，推理落后时丢弃旧帧，不能排队累积延迟；
- 帧缓冲与输入张量预分配并复用；
- 捕获、推理、状态机和输入不得运行在 UI 线程；
- UI 刷新 5-10 Hz，诊断预览默认关闭且最多 5 FPS。

30 FPS 是端到端目标，不是已经测得的结果。当前 C# 管线已具备最新帧缓冲、双模型后处理和安全停止路径，但捕获适配器与正式模型尚未完成；最终是否达标以正式模型在 C# 管线中的帧龄和现场表现为准。

## 4. 状态机与输入安全

| 状态 | 进入条件 | 动作 | 失败处理 |
|---|---|---|---|
| `IDLE` | 启动或上一轮结束 | 左键抛竿 | 进入等待 |
| `WAITING_BITE` | 抛竿稳定 | 等待连续 `prompt` | 超时后复位重抛 |
| `HOOKING` | 咬钩确认 | 左键收钩 | UI 未出现则复位 |
| `MINIGAME` | 连续发现小游戏 UI | 按住/松开左键跟随目标 | 缺关键目标立即释放 |
| `LOOT` | 小游戏 UI 连续消失 | 收杆、拾取 | 超时进入下一轮 |
| `RECOVERY` | 超时或连续失败 | 释放输入并复位 | 延迟后重新开始 |

感叹号、小游戏 UI、成功和失败都必须由连续的新推理结果确认。缓存的 locator 结果不能重复计为多帧证据。

安全要求：

- 默认进入“仅观察”，不得自动发送输入；
- 自动运行前验证模型、显示器、VRChat 窗口和实际 Provider；
- 关键目标缺失、帧过旧、捕获中断或推理异常时立即释放鼠标；
- `F8` 全局紧急停止独立于 UI 线程，在任何状态都能释放鼠标；
- 停止和退出操作必须幂等，异常也不能留下按住状态。

## 5. WinUI 3 前端

主窗口是紧凑的 Windows 工具界面，不持续播放完整屏幕：

| 页面 | 内容 |
|---|---|
| 运行 | VRChat 状态、仅观察、自动运行、停止、当前阶段和实际 Provider |
| 模型 | 下载、更新、删除、版本、文件大小和完整性 |
| 设置 | 显示器、设备、VRChat 窗口、识别阈值和超时 |
| 诊断 | 推理延迟、帧龄、CPU/内存、日志和可选低帧率预览 |

界面使用 WinUI 3 原生 Fluent 控件、明暗主题、系统强调色与可选 Mica。布局不使用营销式大标题、堆叠卡片、大面积渐变或持续动画。“仅观察”和“自动运行”必须在文字、图标和状态色上明确区分。

界面语言资源由随应用编译的 `.resw` 提供简体中文和 English。它们随 Setup 安装，不是 GitHub Release 资产；安装器的语言选择用作首次启动默认值，用户以后可在软件内切换，不需要单独下载语言包。当前 UI 仍在逐步把硬编码文本迁移到资源键，资源文件本身已纳入工程。

## 6. 配置与本地文件

应用以 `VrcFisher.exe` 所在目录作为软件根目录。模型、配置、日志、下载暂存与诊断产物只能写入用户选择的安装目录，具体结构见 [安装与发布](installation-and-release.md)。

这一要求意味着安装目录必须对当前用户可写。应用不能把运行数据转移到 `%LOCALAPPDATA%`、`ProgramData`、用户主目录或注册表数据目录。

## 7. 实现顺序和完成条件

1. 建立 C# 分层解决方案和可测试的状态机，不接真实鼠标。
2. 接入 Windows Graphics Capture 与最新帧缓冲。
3. 实现两个 ONNX 会话、预处理、后处理和录屏回放。
4. 完成观察模式，验证状态转换和故障释放。
5. 接入真实鼠标与全局 `F8`。
6. 完成 WinUI 页面、模型管理和诊断。
7. 在 CPU-only 与 DirectML 下完成性能和现场验收。

没有正式数据和两个有效 ONNX 时，可以建立接口、状态机和假数据测试，但不得声称识别链路已完成。
